# Original excavation HUD artwork

Nine new transparent runtime illustrations: credits, relic, bucket, skills, tools, explore, and bronze/golden/volcanic egg identities. These are production UI exports, not concept boards. The egg portraits identify the existing three egg themes; they do not replace or certify world geometry.

`source/` preserves the original flattened RGBA masters from the built-in image-generation tool. There are no layered painting sources. `prepare_exports.py` crops the atlas cells, preserves aspect ratio/alpha and fits them into padded **256×256** runtime PNGs in `exports/`. `manifest.json` records hashes and actual returned Roblox image IDs. The first upload was the required bucket asset; only after success were the other eight uploaded through the existing Studio MCP connection. No IDs invented.

Production prompts: a transparent 3×2 atlas with six centered subjects (egg-emblem gold coins, violet crystal, blue mineral bucket, branching lightning with star nodes, pickaxe crossed with orange drill, expedition map/compass); bold dark-indigo contours, broad two-tone shadows, clean silhouettes, sunflower/sky/tangerine/violet palette, readable at 48 pixels, no text, frames, grime, branding or background. Separate transparent 3×1 egg atlas: ivory/bronze ancient mineral-ceramic egg, gold-faceted sovereign egg, charcoal basalt/orange-crack volcanic egg; matching bold illustration style, familiar egg silhouettes, no creatures, crowns, glow haze or platforms. Runtime exports perform cropping/resizing only.

Resources reviewed: [UI Labs](https://github.com/PepeElToro41/ui-labs) (GPL-3.0 project), [Vide](https://github.com/centau/vide) (MIT), [Kenney UI Pack](https://kenney.nl/assets/ui-pack) (CC0), and [official Studio MCP](https://create.roblox.com/docs/studio/mcp). No third-party art/library was incorporated and no software was installed. Production factories support direct Edit previews, making a new preview integration/framework migration unnecessary for this checkpoint. Keep the existing Studio connection.

Reused only the existing actual owned tool models via `EquipmentPreview`, so item portraits correspond to equipped equipment. Their model quality remains unapproved; rejected concept models are not used. The previous navigation atlas, skill-node artwork, palette and HUD layout are not the foundation of this HUD. Existing unreplaced menu art remains pending a later checkpoint.
